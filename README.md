# DebtPlan — «Долговой план»

Локальный калькулятор порядка погашения долгов. Пользователь вводит список
кредитных продуктов и сумму, которую он может направлять на погашение каждый
месяц. Приложение считает переплату, срок и дату полного погашения, автоматически
выбирает оптимальную стратегию, позволяет сравнить стратегии между собой
(включая заданный пользователем порядок) и строит помесячный график платежей.

Приложение работает полностью в браузере. Данные не отправляются на сервер и
хранятся только в `localStorage`.

## Стек

- React 19
- Vite 8
- JavaScript (ES modules)
- Vitest + React Testing Library + jsdom (юнит-, компонентные и интеграционные тесты)

## Команды

Установка зависимостей:

```bash
npm install
```

Запуск dev-сервера (http://localhost:5173):

```bash
npm run dev
```

Сборка продакшн-версии в папку `dist/`:

```bash
npm run build
```

Предпросмотр собранной версии:

```bash
npm run preview
```

Запуск всех тестов (однократно):

```bash
npm test
```

То же самое явной командой:

```bash
npm run test:run
```

Режим наблюдения за изменениями файлов:

```bash
npm run test:watch
```

## Автоматические тесты

Тесты разделены на юнит-уровень и уровень компонентных/интеграционных проверок:

- `tests/payoff.test.js` — юнит-тесты расчётного модуля и стратегий (FE-021);
- `tests/*.test.js` — юнит-тесты параметров расчёта, пользовательского порядка и хуков;
- `tests/requirements/` — компонентные и интеграционные тесты ключевых
  требований из backlog.

### Покрытые требования

| Требование | Файл | Что проверяется |
| --- | --- | --- |
| **FE-007** Валидация формы добавления долга | `tests/requirements/FE-007.debt-form-validation.test.jsx` | Пустая форма не отправляется, показываются ошибки у остатка, ставки и минимального платежа. Корректные данные передаются в `onSubmit`, название обрезается по краям. |
| **FE-009** Удаление долга с подтверждением | `tests/requirements/FE-009.debt-deletion.test.jsx` | По кнопке «Удалить» открывается диалог подтверждения, долг не удаляется до подтверждения. «Отмена» закрывает диалог и сохраняет оба долга. После подтверждения строка исчезает, итоги пересчитываются, `localStorage` обновляется. |
| **FE-006** Форма добавления долга | `tests/requirements/FE-006.add-debt.test.jsx` | Кнопка «Добавить долг» открывает форму. После сохранения долг появляется в таблице, итоги по остаткам и минимальным платежам пересчитываются, запись сохраняется в `localStorage`. |
| **FE-021** Юнит-тесты модуля расчёта | `tests/payoff.test.js` | Проценты, закрытие долга, каскад минимальных платежей, срок, дата погашения, переплата, стратегии, недостаточная свободная сумма и предел расчёта в 600 месяцев. |

(`tests/customOrder.test.js`, `tests/requirements/custom-order.test.jsx`),


### Настройка тестового окружения

- `vite.config.js` подключает `environment: 'jsdom'` и файл настройки
  `src/test/setup.js`;
- `src/test/setup.js` регистрирует DOM-матчеры `@testing-library/jest-dom`,
  очищает DOM после каждого теста и добавляет заглушку `window.matchMedia`,
  которой нет в jsdom;
- компонентные тесты используют `@testing-library/user-event`, поэтому
  действия выполняются так же, как пользователем: ввод, выбор, нажатия;
- интеграционные тесты рендерят `App`, предварительно заполняют `localStorage`
  и проверяют итоговое состояние интерфейса и хранилища.

Проверка качества перед сдачей:

```bash
npm test
npm run build
```

## Допущения расчёта

- Проценты начисляются раз в месяц до платежа: месячная ставка = годовая / 12.
- Минимальные платежи берутся из договора; после закрытия долга его минимум
  автоматически достаётся следующему в порядке погашения.
- Досрочные платежи распределяются по порядку стратегии; при заданной
  безрисковой ставке долги дешевле накоплений гасятся только минимумами.
- Оптимальная стратегия помечается автоматически: минимум переплаты,
  при равенстве — кратчайший срок.
- Комиссии, страховки и штрафы не учитываются; поддерживается только рубль.

Расчёт носит справочный характер и не является финансовой рекомендацией.
